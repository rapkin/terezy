# Data model: 016-real-ovdp

No record changes and no new interface (FR-029). What follows is the shape of the files this
feature writes, against the schema that already exists.

## `data/observations/nbu_depository.toml` — new

Generated by `scripts/fetch_nbu_depository.py`. Read by tests; read by nothing at run time.

```
retrieved_on = "YYYY-MM-DD"
endpoint     = "https://bank.gov.ua/depo_securities?json&date=YYYYMMDD"

[[issue]]                       # one per register entry, 195 today
isin, nominal, val_code, pgs_date, razm_date, auk_proc, pay_period,
total_bonds, emit_name, emit_okpo, cptype, cpdescr, cptype_nkcpfr, cpcode_cfi
kind = "bond_terms", source, retrieved_on, verified_on = ""

  [[issue.payment]]             # one per payment row, 3 634 today
  pay_date, pay_type, pay_val
  kind = "bond_terms", source, retrieved_on, verified_on = ""
```

Every table carrying a number or a date carries the four citation keys, because
`scripts/check_provenance.py` walks `data/observations/` and recurses into arrays of tables.
`verified_on` is empty throughout: a retrieved figure is not a checked one.

## `data/instruments/UA4000######.toml` — 24 new files

013's `enumerated_schedule` form, unchanged. Per issue:

| Table | Field | Source |
|---|---|---|
| `[instrument]` | `id` | the ISIN, and nothing else (FR-002) |
| | `name` | the issuer's own «Облігації внутрішньої державної позики» plus the ISIN |
| | `class` | `enumerated_schedule` |
| | `currency` | depository `val_code` |
| | `is_synthetic` | `false` — the first declarations for which it is |
| | `groups` | `["ovdp"]` |
| `[instrument.schedule]` | `face_value` | depository `nominal` |
| | `covers_from` | depository `razm_date` (research D3) |
| | `day_count` | `act/365`, the fixtures' convention (FR-010) |
| | `published_in_order` | **absent** (research D4) |
| | citation | the depository, with the endpoint URL and the retrieval date |
| `[[instrument.schedule.payment]]` | `on`, `amount` | depository `pay_date`, `pay_val`, transcribed with **no conversion** |
| | `pays` | `coupon` for `pay_type = 1`, `principal_repayment` for `2` |
| `[instrument.constraints]` | `min_ticket = 1000.0`, `min_unit = 1.0` | the venue's dealing terms (research D5) |
| `[instrument.tax_classes]` | `coupon`, `disposal_gain` | `ua_government_bond` (FR-026) |
| `[[instrument.verification_task]]` | four, one per member of the gate's closed set | what the data-only decision costs (FR-011) |

**Absent by the form and by FR-007**: `maturity_date`, `coupon_rate_pct`, `issue_date`,
`periodicity`, `business_day_rule`. The schema has no field for any of them, so a file
supplying one fails at load naming the field.

## `data/access/instruments.toml` — 24 new `[[access]]` entries

```
[[access]]
instrument_id = "UA4000######"
bought_at     = "inzhur"
proceeds_to   = "inzhur"
risk_class    = "sovereign_debt"

  [access.price]          per_unit = the seller's buy,  kind = "venue_terms", the seller's citation
  [access.resale_price]   per_unit = the seller's sell, kind = "venue_terms", the seller's citation
```

Both quotations carry the **seller's** source and its retrieval date, and neither citation
mentions the depository (FR-020). The resale price is what closes 015 FR-031 (research D7).

## What is declared nowhere

`available_quantity`, `status`, `return_rate_buy_pct`, `return_rate_sell_pct`, `matures_on`,
`auk_proc`, `pay_period`, and the buy-versus-sell gap. Each is either the seller's forecast
about itself, a snapshot that decays in hours, or a term the form forbids.
